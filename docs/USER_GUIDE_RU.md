# GUI: Audion Doc to PDF

GUI — рабочая оболочка над тем же CLI. Слева находятся канонический Workbench I/O и операции, справа — статус, прогресс и потоковый журнал.

## Workbench I/O

Workbench не копирует документы и не создаёт промежуточный кэш. Строка `Source` указывает непосредственно на папку либо один Office/PDF-файл, строка `Target` — на папку результата. При первом запуске используются проектные `input` и `output`.

У каждой строки есть закрепление пути, блокировка изменений, удаление содержимого и выбор через системный пикер. В списке истории закреплённые пути остаются наверху. `Сбросить` возвращает `input/output` и сохраняет закрепления. Удаление внешнего Source требует отдельного подтверждения; корень диска и корень проекта защищены.

Панель действий содержит `Добавить файл`, `Добавить папку`, `Открыть`, `Список`, `Сбросить` и `Удалить всё`. Выбор файла или папки только меняет текущий маршрут — исходные данные не переносятся.

## Конвертация

Экран конвертации использует текущие Source и Target:

- папка Source сканируется рекурсивно, а её структура зеркалируется в Target;
- одиночный Office-файл конвертируется прямо в Target;
- чекбоксы задают форматы для пакетного сканирования;
- для PowerPoint доступны пост-кадрирование `16:9`/`A4-A3` и уменьшение содержимого.

Поддерживаются Word, Excel и PowerPoint через установленный Microsoft Office desktop.

## Работа с PDF

Все PDF-операции также используют текущие Source и Target. Source может быть PDF-файлом либо папкой с PDF.

- разрезание страниц по вертикали или горизонтали 50/50;
- сохранение первой и последней страниц без разрезания;
- кадрирование под `16:9` или A-серию;
- обрезка полей в миллиметрах;
- нумерация страниц;
- масштабирование содержимого без изменения размера страницы;
- metadata-based кадрирование PDF, экспортированных из PowerPoint.

## Журнал и завершение

GUI показывает фактическую CLI-команду и её вывод. Индикатор остаётся серым в ожидании, синим во время работы, зелёным при успехе и красным при ошибке. `Logs`, `CONFIG` и `Report` открывают служебные папки; журнал можно развернуть.

Пикер допускает только один активный диалог и привязан к жизненному циклу приложения. Закрытие pywebview завершает сервер и его дочерние процессы без отдельной консоли.

## Темы и окно

Язык и тема переключаются в шапке. Настройки сохраняются в `config\gui_settings.yaml`, палитры находятся в `config\ui_colors.yaml`. Desktop-окно фиксировано на `1280x800`; браузерный режим включается только явно через `window.py --browser`.

`Doctor` проверяет runtime, `pypdf`, PowerShell и Office COM. `Инфо` показывает поддерживаемые форматы и текущие настройки.
## Канонические названия Workbench

Workbench использует единый публичный словарь Audion Image Tools во всех проектах. Кнопки всегда расположены и называются одинаково: **Источник**, **Добавить файл...**, **Назначение**, **Сбросить**, **Удалить**, **Список**.

`Сбросить` возвращает проектные `input/output` и не удаляет файлы; `Удалить` очищает текущие `Источник` и `Назначение` только после подтверждения. В английском интерфейсе точные названия: **Source**, **Add file...**, **Target**, **Reset**, **Delete**, **List**. Варианты `Цель`, `Очистить`, `Destination` и `Clear` для этих элементов Workbench не используются.
